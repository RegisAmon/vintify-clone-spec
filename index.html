Vintify-clone — Spec MVP

Clone mécanique d'un SaaS « photos pro IA pour vendeurs Vinted ». Le produit de référence définit la spec ; nom/copy/design réécrits de zéro.

1. Résumé exécutif

L'utilisateur photographie un vêtement à plat → l'IA analyse (type, genre, taille, état, marque, couleurs) → génération de photos « catalogue » : portées par un mannequin IA avec pose et ambiance choisies, ou à plat → l'IA rédige titre, description et hashtags → annonce complète dans « Mes annonces », prête à copier-coller. Monétisation : abonnements mensuels (6 tiers) + packs ponctuels, quotas par plan.

2. Personas

  • Vendeur occasionnel — 2-10 annonces/mois, sensible au prix → Starter / packs.
  • Power seller — 50+ annonces/mois, mannequins réutilisables, qualité 4K → tiers hauts.
  • Admin — users, quotas, poses/fonds, prompts, storage, coût réel.

3. Features MVP

3.1 Wizard 5 étapes (chaque étape ré-ouvrable via « Modifier »)

  1. Photo de l'article — upload / prise photo / collage, max 5. Analyse vision auto : type (haut / bas / couvre-chef), genre, taille, état, couleurs, marque, capuche/poches.
  2. Détails — pré-remplis, éditables. États : Neuf avec étiquette / Neuf sans étiquette / Très bon état / Bon état / Satisfaisant.
  3. Type de photo — Porté par mannequin / À plat (plié face, dos, manches rentrées).
  4. Modèle — Adulte / Enfant, genre, ou mannequin sauvegardé (plans IA).
  5. Pose + ambiance — poses multiples (Face, Dos, 3/4, Selfie sans visage, Capuché, Assis, plié…) ; 12 ambiances (Studio, Fond noir/blanc/gris, Chambre vintage, Dressing, Salon, Balcon parisien, Nature, Table shooting, Magazine).

3.2 Génération

  • Jobs async : createTask + callback, progression SSE, idempotence, coût réservé au lancement puis débité au réel au callback.
  • Qualité par plan : 1K / 2K / 4K. Améliorations IA par presets (« couleurs fidèles », « moins de plis », « tissu naturel », « print net », « t-shirt opaque »).

3.3 Mannequins IA (plans IA)

  • Création via photo de référence OU paramétrique : genre, âge 18-52, origine, yeux, cheveux, morphologie, expression, détails distinctifs, style (E-commerce / Lifestyle / Neutre), curseur de variation 0-100% selon plan.
  • Galerie « Mes mannequins » réutilisables dans le wizard.

3.4 Rédaction & annonces

  • Titre + description + hashtags par LLM (quota rédactions).
  • Mes annonces : fiche complète, copie/telechargement, historique.

3.5 Crédits

  • Quotas : images, annonces, rédactions, mannequins — trackés en DB (jamais le client).
  • Free : 2 annonces + images offertes. Échec API = refund automatique.

3.6 Services IA — Repassage & Essayage

Deux services optionnels, activables par plan, au-dessus du moteur de génération commun. Règle absolue : l'utilisateur ne voit jamais de prompt. Il choisit un service, fournit ses images, reçoit une image. Le prompt est composé côté serveur et n'est exposé ni dans l'UI, ni dans une réponse d'API, ni dans un message d'erreur.

3.6.1 Repassage

Affiche le vêtement repassé — plis lissés, tissu net.

  • Entrées : image (obligatoire, 1 photo — à plat, sur cintre ou porté) · presentation (flat | hanger | worn, pré-détectée par vision, confirmable) · intensity (light | standard | strong) · finish (steam vapeur naturelle | pressed marqué au fer) · background (keep par défaut | white_studio).
  • Sortie : 1 image. Coût : 1 crédit image.

3.6.2 Essayage virtuel

Habille un modèle avec le vêtement fourni.

  • Entrées : garment.mode (single 1 image | set_together haut+bas sur une photo | set_split haut et bas séparés — le haut seul est optionnel) · model.ref (mannequin_id du catalogue Vintify, 16 modèles, ou photo uploadée, toujours résolu en 1 seule URL de référence) · pose.ref (pose_id parmi les 102 références, ou from_photo pour respecter la pose de la photo modèle) · scene (background, framing full | half | magazine, ratio) · garment.attrs (analyse vision : type, taille, couleur, matière, coupe).
  • Sortie : 1 image. set_split déclenche 2 passes séquentielles (haut puis bas, la sortie de la passe 1 entre dans la passe 2) mais 1 seul crédit consommé côté client — le coût réel des 2 appels gateway reste tracé pour surveiller la marge.

3.6.3 Contrat technique commun

  • Provider unique : ArvGateway, modèle defapi:gpt-image-2-edit — POST /v1/generate, header Idempotency-Key obligatoire, params.images[] = URLs R2 signées, callback_url.
  • Limites réelles du modèle : prompt ≤ 4000 caractères · size plafonné à 1536×1024 · quality ∈ low | medium | high.
  • Conséquence : les paliers « HD 2K » et « Ultra 4K » n'existent pas en sortie native. Option retenue par défaut : étape d'upscale post-génération, à confirmer avant de figer les libellés tarifaires.
  • Cohérence d'identité : gpt-image-2-edit ne garantit pas un persona réutilisable d'une génération à l'autre (le visage dérive). Si « mannequin IA réutilisable » reste une promesse produit, un modèle d'identité (flux-kontext / seedream) doit être ajouté au gateway — décision ouverte.

3.7 Moteur de prompts (interne)

Les prompts sont des données versionnées, jamais du code ni du texte utilisateur.

  • 5 blocs, ordre fixe : INTENT (tâche) → PRESERVE (invariants : couleur, motif, logo/texte, boutons, coutures, coupe) → SUBJECT (liaison aux images de référence) → SCENE (pose, cadrage, fond, lumière) → OUTPUT (photoréaliste, ratio, qualité, pas de texte ni watermark).
  • Whitelist stricte : {{garment_type}}, {{colour}}, {{pattern}}, {{material}}, {{size}}, {{model_description}}, {{pose}}, {{framing}}, {{background}}, {{lighting}}, {{ratio}}, {{preserve_notes}}. Une variable hors whitelist fait échouer la génération — aucun fallback silencieux.
  • Aucune entrée libre n'atteint le prompt : l'utilisateur n'alimente que des enums validés.
  • Templates multilingues FR/EN — la version envoyée au modèle reste en anglais.
  • Versioning + rollback, preview « tester » = génération réelle avant publication.
  • Sorties d'analyse vision = enums, jamais du texte libre traduit.

3.8 Espace admin (owner)

3.8.1 Utilisateurs & crédits

  • Liste, recherche, détail : abonnement, quotas, historique, dernier paiement.
  • Crédits : ajout ou retrait manuel (+N / −N) avec motif obligatoire et trace dans credit_transactions (kind grant | revoke, admin_id, reason, balance_after). Opération idempotente : double-clic = un seul mouvement.
  • Révocation : suspendre un compte (login refusé, sessions invalidées), révoquer les sessions actives, réactiver. Un compte suspendu conserve ses données.
  • Refunds automatiques visibles + déclenchement manuel possible.

3.8.2 Prompts par service

  • CRUD par service (repassage, essayage, studio, rédaction) : édition par formulaire, placeholders autorisés rappelés à l'écran, aucune saisie libre non validée.
  • Preview « tester » (génération réelle), activation/désactivation, versions + rollback.
  • Jamais lisibles par un compte utilisateur, y compris via l'API.

3.8.3 Catalogue

  • Poses (102 importées), fonds, mannequins Vintify (16) — ordre d'affichage, activation, libellés multilingues.

3.8.4 Plans & pricing

  • Quotas et prix modifiables sans code, avec test des paliers.

3.8.5 Jobs & coût réel

  • Liste des jobs, coût réel par génération, taux d'échec, remboursements — c'est cette donnée qui fixe les prix finaux.

3.8.6 Storage

  • Usage R2, rétention 90 jours, rotation.

3.8.7 Journal d'audit

  • Toute action admin sensible est tracée : qui, quoi, quand, valeur avant/après.

3.9 Internationalisation (v1 : FR + EN)

  • v1 : français (défaut) et anglais. Allemand, italien, espagnol en phase 2 — une langue de plus = 1 fichier de messages + 1 entrée de config.
  • next-intl, routes app/[locale]/…, middleware (cookie > Accept-Language > FR), URLs /fr/… et /en/…, hreflang + canonical + sitemap multilingue.
  • Deux langues distinctes, jamais confondues : users.ui_locale (interface, emails) et ads.listing_language (titre, description, hashtags). Le wizard demande la langue de l'annonce, pré-remplie mais modifiable.
  • Traduits : UI, emails, prompts IA. Non traduit : le légal (anglais uniquement, LLC Wyoming).
  • Préparer DE/IT/ES : libellés d'action courts, boutons en largeur fluide, aucun format de date ou de nombre écrit à la main (l'allemand est ~30 % plus long).

8. Sécurité & légal (revue critique)

  • Proxy BFF relaie toujours l'Authorization Bearer au backend ; gating backend sur les médias (URLs signées, jamais le « blur CSS »).
  • Idempotency sur tout achat/génération ; webhooks Stripe vérifiés ; aucune route legacy non signée.
  • Quotas : DB fait foi ; le seed admin n'écrase jamais un hash ; 429 rate-limit ≠ bug de mdp.
  • RGPD : export (art. 20) + suppression en cascade (art. 17) + CGU/Privacy/Cookies.
  • Prompts : compositions serveur uniquement — aucun prompt dans l'UI, les réponses d'API, les messages d'erreur ou les logs renvoyés au client. Variables à whitelist stricte.
  • Admin : tout mouvement de crédit manuel porte un motif et une trace (admin_id, avant/après) ; suspension = sessions invalidées, pas seulement un drapeau en base.
  • Marque : aucun nom, logo, texte ou asset de la cible. Mécaniques seules clonées. Mention produit : « le vêtement source n'est jamais altéré » (garantie Cloth-Preserve).

9. Critères de succès

  • E2E : inscription → free credits → wizard → annonce générée (images + texte) < 60s/génération.
  • Échec API = refund vérifié en DB.
  • Isolation : le compte B ne voit jamais les données de A (404, jamais 403).
  • Paiement test : crédits en < 5s, double-clic = un seul paiement.
  • Wizard complet utilisable en 480px.
